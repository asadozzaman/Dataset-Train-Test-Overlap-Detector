How these percentages are calculated

SSIM compares local structure after EXIF orientation, grayscale conversion and resizing to 128 × 128 pixels. The reported percentage is SSIM × 100, clipped at zero, using uniform 7 × 7 windows, sample covariance, and a pixel range of 255. Perceptual agreement is the matching fraction of 64 dHash bits.

Neither score is a probability or proof of shared origin. Color changes, crop, alignment and low-detail images can produce misleading scores. The CPU checker reviews at most 2,000 images and scores at most 500 candidate pairs.

04 / RESEARCH & DOCUMENTATION

Evidence has boundaries.
We keep them visible.

Independent open-source work. Public source references, inspectable configurations, and measurements you can rerun.

What the checks establish

Exact overlap
Shared resolved paths or identical SHA-256 file digests. Decoded pixel equality is a different check.
Appearance candidates
dHash distance ≤ 6, followed by grayscale SSIM at 128 × 128. No SSIM cutoff determines leakage.
Recording context
Video and session checks use reviewed provenance CSV assertions. These examples supply no verified recording histories.

What remains unknown

  • Zero exact matches cannot establish freedom from every form of leakage.
  • Similarity does not prove shared origin or evaluation dependence. Color, crops, alignment and low-detail scenes can mislead.
  • Optional similarity is limited to 2,000 unique images and 500 scored candidate pairs. Truncation is disclosed.
  • The tool does not assess annotation quality, dataset diversity, or model generalization.

Reproduce these four experiments

From the cloned repository, install the similarity extra, verify/download the official COCO archives, fetch the pinned benchmark originals, then build. The builder reruns the auditor and writes the reports and experiment manifest.

python -m pip install ".[similarity]"
python scripts/verify_public_datasets.py --download --output reports/public-check
python scripts/fetch_similarity_examples.py
python scripts/build_showcase.py --output reports/reproduced --github-url https://github.com/asadozzaman/Dataset-Train-Test-Overlap-Detector

Use fresh output directories. Each experiment record includes its configuration, original input digests, runtime versions, engine fingerprint and reproduction command. For a single experiment, download its configuration and place the source files as described in the manifest.

05 / USE THE LOCAL TOOL

Your next audit
starts with one file.

Clone the repository, install the auditor, then point it at your YOLO configuration. Replace the example path with your dataset YAML. Python 3.10+; Windows and Linux.

Configure→Audit→Review
Open an actual report ↗View repository ↗

Installation is from source; no PyPI release. See the repository quickstart for supported inputs and CLI options.

A minimal dataset configuration

Place data.yaml next to your images/ directory. Example paths:

train: images/train
val: images/val
# test: images/test  # optional

At least two configured splits must contain images. The auditor reads local files and leaves them untouched.

Quickstart ↗ · CLI reference ↗

● ● ●
01 / CLONE & INSTALL
git clone https://github.com/asadozzaman/Dataset-Train-Test-Overlap-Detector.git
cd Dataset-Train-Test-Overlap-Detector
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install ".[similarity]"
02 / AUDIT YOUR YOLO DATASET
.\.venv\Scripts\videosplitguard.exe audit "path\to\data.yaml" --near-duplicates --output "reports\first-audit"

Use a new output folder each run. Open reports/first-audit/report.html. Exit 1 means confirmed overlap; 0 means none confirmed, and 2 means an error. A NOT VERIFIED audit can exit 0.
